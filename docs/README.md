## 当前方案

1. 单家庭 Android App，建议 React Native + Expo + TypeScript；FastAPI + SQLite 后端，交付独立签名 APK。技术栈仍待整体审核。
2. 食材分类与菜品分类分开；食材季节多选或全年。取消市场状态表和人工 availability。季节只作为家庭采购近似，不宣称实时有货。
3. SQLite 按分类、季节、确认历史和禁忌检索；LLM 理解用户并从候选挑菜搭配；规则守住计数、硬禁忌、重复和非目标菜不变。
4. 无需向量数据库、embedding 或专用 RAG 框架；保留“检索相关数据后提供给模型”的简单方式。
5. 本餐结构化状态加最近少量消息提供短期记忆；长期只存家庭配置、菜谱、确认记录及明确保存的偏好，不做隐式画像。
6. 最近三天是 Asia/Shanghai 的今天及前两天；确认菜单的菜直接硬排除。评分、模型或候选不足均不能自动解除。
7. 单菜对话调整进入 P0；通用锁定按钮、历史浏览仍在 P1。AI 临时菜主动保存才进入家庭库。
8. 当前系统不含图片字段、上传、图片展示；保持最小菜谱录入和无伪造用量的采购清单。

设计细节见 [01](01_需求审查与范围.md#5-剩余待决项)。M1 采用月份季节月历作可编辑家庭参考，尚未进入 M2 推荐或 M3 模型阶段。
