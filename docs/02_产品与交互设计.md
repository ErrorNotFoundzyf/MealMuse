# 02 产品与交互设计

更新：2026-11-02，Android首版，无业务图片。

## 1. 信息架构

底部四入口：首页、食材、菜谱、设置。采用Tab + Stack，首次配置、菜谱详情/编辑、菜单结果、采购清单为独立屏幕。非网页路由，不做桌面端。首版竖屏、安全区域与Android返回键适配。

首页是“推荐 + 围绕本餐继续调整”，不是独立通用聊天机器人。current context/session ID持久化，重开App恢复当前规划，不提供全量历史页。

## 2. 首次配置与推荐前

人数、各菜品类型数量为必需；总数自动计算。示例可选可改，不能写死四人或固定荤素结构。人数正整数、数量非负整数，总数至少1；工程上限建议人数30、菜数20，待审核。

种子食材与菜谱加载后可直接开始；不再要求逐项维护可购买状态。季节由后端按日期计算，种子季节数据经审核。

```text
今天吃什么
4人 · 荤1 / 素2 / 汤1     [本次调整]
当前季节：秋季（按家庭季节月历）
有什么特别想法？（选填）
[今天不能吃辣，想清淡一点]
[今天吃什么]
已确认菜单中的菜，今天及前两天不再推荐
```

本次调整不保存默认；“保存为默认”是单独明确动作。文本与表单冲突、两菜一汤荤素不明、禁忌映射不清时，只问必要问题。

## 3. 菜单结果与连续调整

菜卡只展示文字：名称、主分类、默认/家庭/AI临时来源、主要食材、季节状态、简短理由和待核对信息。无图片、图片占位或上传入口。

主操作“确认这顿菜单”；次操作“重新推荐整桌”；每菜“换这道”，下方本餐对话输入“想怎么调整？”。

例：“红烧肉太腻了，换一个，其他不变。”
- 指向当前菜ID和槽位，拒绝红烧肉仅记本餐。
- 复制其他菜的完整快照，不让模型改它们。
- 从符合原禁忌、三天排除及季节规则的候选中换同类菜。
- 结果展示“已换红烧肉，其他3道不变”，重算清单。
- 用户再说“不想吃这个”，根据当前桌继续，先前拒绝不丢失。
- 指代不唯一先问；不能猜哪个“这个”。

用户明确“以后都不要”才保存轻量长期偏好（设计建议）；普通“今天不想吃”绝不自动永久保存。新一顿清空本餐临时条件，但家庭默认和三天确认历史保留。

通用锁定按钮留P1；“其他不变”属于本轮操作范围，不把其他菜永久锁住。

## 4. 状态和核对

| 状态 | 行为 |
|---|---|
| generating | 防重复提交，可离开后恢复；不显示虚构进度 |
| needs_clarification | 只问不明确的目标、配置或条件；保留本餐状态 |
| awaiting_confirmation | 配额完整但硬条件信息不足；只能核对具体条件或换菜，普通确认不可用 |
| ready | 完整且硬条件通过，可确认/调整/清单预览 |
| insufficient | 列缺少类型与原因；可展示部分候选，不称完整菜单 |
| failed | 重试或允许的规则降级；解析失败不能丢掉用户文字 |
| confirmed | 固定菜单与清单，立即纳入三天排除，本餐规划关闭 |

季节提示使用“当季/全年”“非当季”“季节未设置”，不说已核实可买。默认不足时询问是否扩展非当季；用户允许也不放松禁忌和三天重复。

核对例：“本次制作是否不使用辣椒及含辣调料？”回答仅为本餐对应条件的证据，不改长期菜谱、不保证医疗安全。明确已知冲突的菜不能靠勾选继续。信息不足的复合食材需核对配料。

确认时重查当前日期和已确认菜单；刚有另一桌确认相同菜时提示需换菜。重复点击确认返回已有确认，不新增记录。确认按钮说明“确认后，这些菜今天及前两天窗口内将被避开”，不要求另点“吃过了”。

已确认结果不原地编辑；再调整新开规划并按当前排除集合执行，不隐含允许重复刚确认的菜。

## 5. 食材和菜谱

食材页按名称/别名搜索，按ingredient_category及season筛选；显示分类、季节、来源。编辑页季节多选春夏秋冬，或“全年”，二者互斥；可留未设置。不再显示可买/不可买按钮。

系统名称只读，但家庭可改季节与隐藏状态；自定义可改名/分类/季节/删。输入别名命中已有食材提示复用；删除有有效菜谱引用时列引用项并拒绝级联删除。

菜谱页按名称、菜品类型、食材、来源搜索；新建仅菜名/主要食材至少1项/主分类必填。步骤、用量、时间、标签、备注折叠选填。空步骤显示“未录入”，不触发AI补完；没有任何图片字段。

默认菜谱只读、可隐藏；家庭菜谱可改删。AI临时菜标“本次建议，尚未保存”，主动保存进入最小表单，映射食材后创建家庭菜谱。未保存不加入正式检索库。

## 6. 设置、采购与设备体验

设置：默认人数/配额、必要连接状态；可选轻量明确偏好列表供删除，不建设画像平台。后端地址优先构建配置，自托管才暴露折叠地址设置，不显示模型密钥。

采购清单按食材ID去重，保留来源菜和季节状态；当季仍需要购买。用量缺失仅列名称，不能按人数给假克数。预览随菜单改变，确认后固定快照。

Android点击区域建议至少48dp，处理中文输入法、系统栏、字体缩放和未保存离开提示。不申请摄像头、麦克风、位置或后台常驻权限。

后台恢复查询原会话，不重新生成；发请求前持久化幂等key。建议缓存最近已确认清单供买菜时断网查看，标时间及当时季节信息；无网不能写库/新推荐，不做同步冲突引擎。该只读缓存仍为待审核建议。
