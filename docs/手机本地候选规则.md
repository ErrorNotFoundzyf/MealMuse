# 手机本地候选与换菜规则

## 候选 1：程序筛选

- 使用可见、未删除、食材记录完整的菜谱。
- 基于当前日期确定季节：3—5 月春，6—8 月夏，9—11 月秋，12—2 月冬。
- 默认要求主要食材当季或全年供应；只有本餐明确允许时才放宽非当季限制。
- 排除今天及前两天已确认食记中的同菜谱或同菜签名。这是硬过滤。
- 分类、荤素汤配额及硬菜数量是组合条件，不应把其他分类从备选中永久删除。

## 候选 2：应用本餐个性化要求

- 明确的食材排除由程序逐项检查，涵盖菜谱已登记的所有配料。
- 清淡、少油等需要语义判断的要求，由模型评估候选 1。
- 模型分批评估完整候选；分批大小只控制单次请求长度，不限制候选总数量。
- 没有语义要求时，满足程序条件的完整候选即为有效备选，无需额外模型筛选。
- 每次对话重新应用本餐要求。不能用模型选择的几道菜代替完整备选。

## 组合与按钮换菜

- 程序从有效备选中按本餐人数、分类数量、硬菜要求组合菜单。
- 甜点和水果作为额外项目，不增加荤素汤总菜数。
- 换一道保持分类及整桌硬菜要求，其他菜不变，避免本桌重复。
- 换一道和换整桌不调用模型；使用已评估的备选，并重新检查最新菜谱、季节、食记及明确忌口。
- 用户主动在自己挑里保留的近期菜可以保留；新自动补入的菜仍严格避重复。
- 按钮以前换出的菜只降低再次选择优先级，不因多次点击而永久清空备选。
- 没有合适替代时保留菜单并说明原因，不放宽硬过滤，也不把未评估语义要求的菜混入备选。
