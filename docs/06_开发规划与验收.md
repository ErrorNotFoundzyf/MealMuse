# 06 开发规划与验收

更新：2026-11-02；用户已批准启动 M1。基础代码、迁移和接口测试已实现，Android 原生构建/真机验收尚受 SDK 环境限制；详细证据见 [M1开发状态](M1_开发状态.md)。以下 M2/M3 测试仍为后续验收计划，不是已通过结果。

## 2. MVP边界

P0包含无图片菜谱/食材管理、季节、家庭配置、SQL检索、LLM挑菜、对话单菜调整、整桌重选、临时菜主动保存、确认与三自然日硬排除、清单和降级。

不做市场实时状态、图片、价格预算、库存、向量检索平台、模型训练、成员画像、iOS、商店发布、离线写入。通用锁定按钮不影响P0对“其他不变”的严格执行。

## 4. 新需求的关键测试

### 日期及确认

- 固定服务端Asia/Shanghai日期2026-11-02：10月31日、11月1日、11月2日已确认菜均排除，10月30日不受该窗口硬排除。
- 自然日边界而非72小时：11月2日23:59仍排除10月31日00:01的确认菜；11月3日00:00后10月31日退出窗口。
- 数据库存UTC，换算后查询；修改请求meal_date不改变当前排除窗口。
- 同日不同餐也不能重选确认过的菜；未确认结果不计入长期排除。
- 确认即生效，不依赖“吃过了”；候选不足不从三天排除集合捞回。
- 两个结果生成时同菜，确认第一桌后第二桌确认必须拒绝/提示调整；检查与写入同事务串行化。
- 重复确认幂等，不把自身当新冲突；生成后跨午夜确认，重算日期季节与排除集合。
- 正式菜、同名同料副本、临时菜保存关联均测试；改名疑似重复核对，不因主料相同误杀所有不同菜。

### 记忆及单菜调整

- “红烧肉换掉，其他不变”：只有目标槽位变化，非目标快照/分类/数量不变，清单重算。
- 连续拒绝A、B，第三轮不返回A或B；超出最近消息窗口后结构化拒绝/禁忌仍保留。
- “这个不要”有多重指代时先问；不得随意换错菜。
- “今天太腻”只影响本餐；“以后别推”才写明确长期偏好；无隐式永久画像。
- 本餐重开App恢复状态；新一顿清临时拒绝，不清家庭默认/确认历史。
- 同context并发操作使用expected_session_id；旧响应不能覆盖新桌。
- 模型/网络失败保留已接受条件，重试不重复记录消息/收费生成。

### 季节与数据

- 食材分类与菜品分类不能混用；春夏多选、全年互斥、未设置均正确。
- 当前月历边界11月30日→12月1日重算；模型输入采用后端时间，不猜季节。
- 默认食材允许编辑家庭季节但不改系统名称；隐藏主料关联菜不自动召回。
- 无市场状态表、API、三态按钮及业务图片字段/上传入口。
- 外键与逻辑删除检查；引用食材删除409，旧推荐快照不变；别名归一冲突提示复用。
- 临时生成未知食材ID拒绝；主动保存失败全回滚。

### LLM与硬约束

- 模型选择仅来自允许候选，不能自造ID或解除三天排除。
- 明确禁忌检查包括已知辅料；配方空/复合配料未知不得推断安全。
- 提示注入、漏硬检查、错误证据、非目标菜被改、重复菜输出均拒绝或待核对。
- 模型不传全库/全部聊天，不自动写正式菜谱或家庭配置。
- 首批候选不足需扩展；预算耗尽标评估未完成，不假说全库无菜。

## 5. 测试层次和交付检查

固定小数据集包含每类多菜、各季/全年/未设置食材、辛辣/配方稀疏/复合食材、共享主料、跨日确认及临时菜。算法测试用固定输入，模型用假响应覆盖故障；少量真实模型抽查并记日期/标识，不把一次回答当可靠性证明。

pytest验证过滤/窗口/季节/事务/幂等/API；移动端组件测试验证表单状态；Maestro真机/模拟器覆盖安装→首配→推荐→对话换菜→确认→清单。业务不变量为重点，不为简单文案写机械测试。

性能初值：约1000菜谱规则路径本机p95目标<1秒，模型每轮总预算45秒；未测量不能宣称达标。备份需恢复演练，模型密钥不进APK。Android验证返回键、中文输入法、字体缩放、后台恢复、杀进程与覆盖升级；release独立启动无需开发服务器，联网业务仍依赖后端。

若采纳只读清单缓存：飞行模式可查看最近已确认清单并标时间，不允许离线新推荐/编辑；不引入同步引擎。
