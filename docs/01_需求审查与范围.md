# 01 需求审查与范围

更新：2026-11-02。原 PRD 保留，本轮用户变更优先于原文及旧版设计。

## 1. 当前需求基线

原 PRD 的单家庭、整顿饭规划、最小录入、采购清单及规则与 LLM 协作继续成立。

| 项目 | 当前决定 | 取代旧方案 |
|---|---|---|
| 客户端 | Android App、独立 APK | Web/PWA 建议 |
| 图片 | 当前无图片业务及数据库图片字段 | image_url 预留 |
| 食材分类 | ingredient_category：蔬菜/肉类/菌菇等 | 含义不清的 category |
| 食材季节 | 春/夏/秋/冬多选，或全年 | 人工可购买状态 |
| 市场状态 | 取消 MarketIngredient 与人工 availability | 动态供应三态 |
| LLM | 理解对话、选择和搭配候选、补临时菜 | 主要由评分决定整桌 |
| 记忆 | 轻量本餐记忆，支持只换一道、其他不动 | 单菜调整全部放 P1 |
| 避重复窗口 | 已确认：今天及前两天自然日 | 最近7天扣分、滚动72小时 |
| 避重复依据 | 已确认：确认菜单即计入，窗口内硬排除 | 另点“吃过了”或只扣分 |

具体字段、调用预算仍是工程细节。用户后续已明确批准启动 M1；当前季节月历采用月份默认，并允许家庭修改食材季节。开发进度以 M1 开发记录为准。

## 2. 需求冲突的裁决

1. 对话单菜调整进入 P0；非目标槽位由服务端冻结，不能只靠模型承诺。通用锁定按钮仍在 P1。
2. 季节状态表示家庭采购近似，不是核实市场现货。推荐“当季”，不说“已确定可购买”。
3. 最近三天重复是硬过滤，不能由高分抵消。候选不足要补其他菜或明确不足。
4. 确认是避重复依据，不声称用户确实吃过；不再增加“吃过了”必点入口。未确认推荐不进入长期排除。
5. 分类计数为唯一真相，总数派生。文本与本次表单冲突要问；“两菜一汤”未指明荤素时不能自行分配。
6. 硬禁忌已知冲突直接排除；配方不全可展示为待核对候选，unknown 未解决不能普通确认。
7. 菜谱来源仅 default/family；ai_temporary 只存在推荐快照，主动保存后才入家庭库；生成不创建食材目录。
8. 推荐清单先预览、确认后固定；按食材 ID 去重，不扣“家里已有”，不从人数猜克数。

## 3. 遗漏与建议

| 问题 | 建议 | 影响 |
|---|---|---|
| 季节月历 | 后端取真实时间并转 Asia/Shanghai；建议3—5月春、6—8月夏、9—11月秋、12—2月冬 | 月历是待审核产品默认，不是气象或地域结论；不定位查天气 |
| 季节未填写 | season_unknown，不默认为全年 | 不阻止最小家庭菜录入；种子季节需要人工审核 |
| 默认食材季节编辑 | 系统名称只读，家庭可编辑季节和隐藏状态 | 单家庭无需另建多租户覆盖表 |
| 日期基准 | 排除窗口按服务端今天，不按可填的 meal_date | 防止改餐次日期绕过排除；跨午夜继续/确认须复验 |
| 同菜不同ID | 正式ID、保存关联、规范化名称+主料指纹识别 | 改名疑似重复须核对；主料相同不等于同一道菜 |
| 本餐拒绝 | 只存本餐，不自动成为永久不喜欢 | “以后都不要”才形成明确长期偏好 |
| 确认后再修改 | 保留已确认快照，新开规划会话并读排除记录 | 不设置隐含豁免，刚确认的菜也不能重选 |
| 人数与用量 | 人数作上下文，原用量不自动缩放 | 无数量只列名称；不要求补全配方 |
| 删改引用 | 逻辑删除、引用检查、历史快照 | 不因目录修改破坏旧清单 |
| 数据最小化 | 只发本餐状态、必要候选、少量消息 | 不发全库和全部历史，不建立健康画像 |

## 4. MVP 边界

P0：Android 四入口；配置；食材类别/季节/基本别名；无图片菜谱管理；SQL 检索；规则硬过滤；LLM 挑菜搭配；本餐对话、单菜调整、整桌重选；临时菜补充与保存；确认记录与三自然日硬排除；采购清单和错误降级。

P1：通用锁定按钮、历史浏览、收藏、长期偏好高级管理、场景模板和复杂模糊去重。轻量明确偏好记录属于设计建议，不做成员画像及隐式喜好学习。

不做：图片业务、价格预算、库存保鲜、自动市场采集、向量数据库/embedding/专用 RAG 框架、模型训练、知识图谱、多家庭平台、首版 iOS、离线写入与同步。

## 5. 剩余待决项

Android、三自然日和确认即避重复不再询问。

| 待决项 | 推荐默认 | 影响 |
|---|---|---|
| 季节月历及非当季兜底 | 上述月份划分；先当季+全年，不足提示用户选择是否扩展非当季 | 不静默放宽，不将其误作安全禁忌 |
| 硬禁忌未知 | 核对具体条件或换菜，不提供“忽略” | 稀疏配方不能自动保证安全 |
| API部署/模型服务 | 单家庭 HTTPS API，模型密钥仅后端；提供商待选 | 外出实时推荐需远程可达服务 |
