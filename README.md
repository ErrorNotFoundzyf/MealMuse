# MealMuse · 吃饭灵感

家庭自用的 Android 饮食规划 App，帮助选择菜谱、搭配整桌菜单并记录每天的饮食。当前已实现 **M3：DeepSeek 对话搭配、轻量本餐记忆和临时补菜**，以及规则搭配、自选菜单和食记。

## 当前功能

- 五个导航：食材、菜谱、今日灵感、食记、家庭。
- 食材名称、别名、分类与季节管理，包含调料和水果；预置内容与新增内容统一编辑、删除。
- 菜谱增删改查；普通分类单选，硬菜可附加到另一个分类，最多两个标签。
- 家庭默认人数及荤菜、素菜、汤数量；米饭不计入菜数。
- 规则搭配、单道换菜、整桌重选；自动推荐硬排除今天及前两个自然日已确认的菜，手动选菜允许主动重复。
- 默认只使用当季／全年主要食材，明确开启后才能扩展非当季或季节未知食材。候选不足会说明原因。
- 自选草稿本地保存、确认菜单、日历食记、历史快照、更正和删除；支持补记过去，不记录未来计划。
- 采购清单按主要食材去重；只有用量完整且单位一致才求和，不推算克数。
- 自然语言描述要求、定向替换多道菜并保留其余菜；本餐条件持续保留，失败可重试。
- AI 临时菜可参与本餐和食记，只有主动点击「保存到菜谱库」才入库；缺少配料与做法时要求核对明确的饮食限制。

当前没有业务图片、价格、库存、向量数据库或餐饮经营功能。界面设计稿保留在 `docs/ui`，不是 App 运行资源。

## 技术栈与目录

| 目录 | 内容 |
| --- | --- |
| `mobile/` | React Native、Expo、TypeScript Android 客户端 |
| `backend/` | FastAPI、SQLAlchemy、SQLite、Alembic 迁移及 pytest |
| `scripts/` | Windows 环境、启动、检查及 Android 构建脚本 |
| `docs/` | 产品设计、视觉提案、交互和阶段交付记录 |

后端数据保存在 `backend/data/eating.db`；启动时自动升级迁移并幂等初始化目录，不覆盖用户修改或恢复已删除内容。手机使用 AsyncStorage 保存菜单草稿，SecureStore 保存家庭接入凭证。

## 开发环境

已验证环境：Windows、Node.js 22、Python 3.12、JDK 17；Python 最低要求 3.11。后端安装脚本使用 uv，Android 原生构建还需要匹配 Expo/RN 的 Android SDK、NDK 和 CMake。

移动硬盘路径、所需工具版本及构建问题记录见 [Android 环境说明](docs/Android_移动硬盘开发环境.md)。环境脚本只修改当前终端，不修改系统永久变量。

### 安装项目依赖

在项目根目录打开 PowerShell：

```powershell
# 将解释器路径换成电脑上可用的 Python
.\scripts\setup-backend.ps1 -Python 'C:\Path\To\python.exe'

Set-Location mobile
npm.cmd ci
```

两个 `.env.example` 仅为配置参考，不包含真实凭证。后端读取进程环境变量，不会自动加载 `.env.example`。

### 启动后端和手机调试

将已授权 USB 调试的 Android 手机接入电脑。在根目录的两个 PowerShell 窗口分别运行：

```powershell
# 窗口一：后端
.\scripts\start-backend.ps1
```

```powershell
# 窗口二：USB 端口映射和 Metro
.\scripts\start-android-dev.ps1
```

后端监听 `127.0.0.1:8000`，Metro 使用 8081，脚本将两端口通过 ADB 映射给手机。已安装的开发调试 App 使用 `http://127.0.0.1:8000`；若手机之前保存了其他服务地址，可在家庭页面修改。

开发期间保持移动硬盘、USB 连接和两个服务运行。电脑重启后重新运行上述命令；USB 重接后需恢复 ADB 端口映射。常规 JS/TS 页面修改不需要重建 APK。

健康检查：`http://127.0.0.1:8000/api/v1/health`；本地 API 文档：`http://127.0.0.1:8000/docs`。

局域网绑定前需设置 `EATING_API_TOKEN`，在 App 填相同凭证；对外部署使用 HTTPS，凭证及模型密钥不进入安装包或仓库。

### 配置 DeepSeek

首次使用时，将 `backend/llm.local.example.json` 复制为 `backend/llm.local.json`，仅在本地填写 `api_key`。默认接口为 `https://api.deepseek.com`、模型为 `deepseek-flash`。已存在的本地配置不要覆盖；该文件已被 Git 忽略，不会打入 APK。

也可以设置后端进程变量 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`，它们优先于本地文件。`GET /api/v1/ai/status` 仅返回是否已配置、服务商和模型，不返回密钥。未配置时仍可使用规则搭配和自己挑。

手机进入「今日灵感 → 帮我搭配」，在底部描述要求，如「帮我搭配一餐，家常清淡一点」，再继续说「换掉第一道和汤，另外两道保留」。对话结果仍须主动确认才写入食记。详见 [M3 接入与验收说明](docs/M3_对话搭配_开发状态.md)。

### Android 构建

```powershell
# 所需 SDK/JDK 已安装后，在根目录运行
.\scripts\build-android.ps1
```

已有原生工程时可按环境说明使用 `-SkipPrebuild`，避免不必要地重新生成。`-UseSystemProxy`、`-UseAliyunMirror` 是可选的本地构建参数，不修改全局仓库。

当前产物为依赖 Metro 和后端的开发调试 APK。独立发布包、正式签名和发布流程尚未交付。Expo 名称已配置为「吃饭灵感」，旧安装包的桌面名称需要下次原生构建才会更新。

### 验证

```powershell
# 根目录：后端测试和前端严格类型检查
.\scripts\check.ps1

# 单独检查 Android 客户端类型
npm.cmd run typecheck --prefix mobile
```

测试覆盖数据迁移、持久化、分类及季节、别名、引用完整性、家庭配置、食记快照与幂等、规则推荐、三自然日硬排除、版本冲突、换菜、采购清单、对话记忆、临时菜及模型异常。自动测试使用模拟模型与独立数据库，不消耗真实 API；真机和真实 API 验证范围见阶段记录。

## 仓库约定

依赖锁文件、源代码、迁移、测试、脚本及必要设计文档纳入 Git。依赖目录、本地数据库、环境变量文件、密钥、缓存、日志、生成的原生工程、APK 和临时设备截图不提交。

修改后执行相应检查，再提交可追踪的 commit。真实家庭食记和菜谱数据不会通过代码仓库同步，需要单独保管数据库备份。
